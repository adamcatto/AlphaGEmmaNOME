Inverse Genome Editing Service and Solvers

May 24, 2026

Implemented /optimize_edits endpoint and three advanced inverse state-space solvers:

  • Beam Search (Multi-site SNVs): Evaluates single nucleotide mutations using ISM, selects top candidates, and executes a greedy beam search (beam width 3) up to max_edits to identify synergistic mutations.
  • Sliding-Window Deletion Scanner: Slides a deletion window of lengths 5, 10, 25, and 50 bp across the design region, retaining exact locus sequence lengths by dynamically fetching adjacent genomic bases.
  • Motif-Aware Insertion / Ablation Solver: Inserts canonical consensus sequences (CTCF, SP1, AP-1, TATA, OCT4, NF-kB) across the design region, or searches for and ablates/deletes matches.

Added requests/responses schemas and integrated everything into services/alphagenome_svc/app.py.

Robust Coordinate-Size Alignment for AlphaGenome

May 24, 2026

Identified and resolved a shape mismatch error (einops.EinopsError: Shape mismatch, can't divide axis of length 1801 in chunks of 2) caused by arbitrary coordinate/locus sizes in AlphaGenome's deep UNet convolutional downsampling layers:

  • Discovered that AlphaGenome requires sequence lengths to be exact multiples of 2048 bp due to its multi-stage UNet architectural constraints, and must always be at least 16,384 bp ($2^{14}$ base pairs) to support full downsampling layers.
  • Implemented a robust helper function _adjust_locus_to_multiple(locus, multiple=2048) in services/alphagenome_svc/app.py that symmetrically and transparently expands any arbitrary coordinate range to at least 16,384 bp and aligns it to the nearest multiple of 2048 bp.
  • Applied this automatic coordinate alignment across all AlphaGenome microservice entrypoints: /predict, /attribution, /optimize_sequence, and /optimize_edits.
  • Hot-reloaded the service, successfully verifying that requests with arbitrary locus sizes (like APOE locus of 3,602 bp) are dynamically scaled to 16,384 bp ($2^{14}$) and execute perfectly, finding deletions with -100.0% silencing efficiency on the actual model.

Robust Large-Locus Clipping and Tool Exception Safeguards

May 24, 2026

Identified and resolved a critical bug where requesting edits for large genes (such as SNAP25 with a locus span of ~135kb) caused the agent to produce absolutely empty responses:

  • Root Cause Analysis: Found that Ensembl lookups for large genes exceed AlphaGenome's maximum supported sequence length (131,072 bp). Passing this locus directly to the microservice raised a 400 Bad Request. When the agent backend's comparative visualization step ran _predict on this locus, it propagated an unhandled exception, causing the Server-Sent Events (SSE) chat stream to crash silently and return a completely empty response.
  • Symmetrical Large-Locus Clipping: Updated _adjust_locus_to_multiple in services/alphagenome_svc/app.py to detect if an input locus exceeds 131,072 bp. If so, it symmetrically clips/contracts the coordinate boundaries to exactly 131,072 bp centered on the original locus. Because 131,072 is perfectly divisible by 2048 (the deep UNet block size), this satisfies both maximum length boundaries and network downsampling requirements automatically.
  • Tool Execution Exception Safeguards: Wrapped the dual-prediction block inside OptimizeEdits.forward() (in services/agent_backend/tools/genome_edits.py) within a try-except block. If a prediction or comparative visualization fails for any unexpected reason, the tool logs the warning and gracefully falls back to returning the text/JSON candidates rather than crashing the active SSE stream.
  • Unit Testing Verification: Added a comprehensive regression test test_adjust_locus_to_multiple in tests/test_backend.py to verify that both small expansion (under 16,384 bp) and large contraction (clipping Snap25 from 135kb down to 131,072 bp) function correctly and are perfectly aligned to 2048 bp boundaries. All tests passed.

Classifier Token-Budget Hotfix and Gene-to-Locus Primitive Enablement

May 24, 2026

Resolved a critical bug where multi-step pipeline instructions (e.g. looking up a gene using gene_to_locus and then running optimize_edits) repeatedly failed to invoke any tools or generate responses:

  • Intent Router Cutoff Bug: Identified that the local LLM (gemma4:e4b) is a thinking model that generates significant internal reasoning inside <think>...</think> blocks. The intent classifier in services/agent_backend/nodes/intent_router.py was configured with num_predict=64, causing it to run out of generation tokens before it could emit the final classification word (PREDICT or ANSWER). As a result, the classification was returned as blank, defaulting the graph to the ANSWER (conversational) node.
  • Empty Conversational Tool Call Exit: Under the conversational node, no tools are bound. However, because the user prompt requested tools, the LLM still generated a tool call block. Since the conversational node does not have edges to the tools executor or a synthesizer, the graph exited immediately without producing any text or tool call results, rendering as an empty bubble.
  • Token-Budget Hotfix: Increased the classifier's token limit to num_predict=512 inside _build_llm() in intent_router.py. This leaves ample budget for the model to think and cleanly output the PREDICT classification.
  • Gene-to-Locus Enablement: Enabled the gene_to_locus primitive tool inside config/tools.yaml, allowing the agent to successfully retrieve genomic coordinates from Ensembl by HGNC symbol when requested as the first step of an optimization task.
  • Unit Testing Verification: Added test_intent_router_node to tests/test_backend.py to verify router conditional edges and mock LLM classification outputs. All backend tests pass successfully.

Genomic Context Contraction for Real-time Prediction Speedups

May 24, 2026

Shortened the maximum sequence context length to dramatically accelerate sequence edits optimization runtimes on CPU:

  • The Speed Bottleneck: Found that running sliding window deletions or beam search SNVs over large regions of interest triggers hundreds of back-to-back forward passes of the neural network. On a $131,072\text{ bp}$ ($128\text{ kb}$) locus, each single forward pass on the CPU takes around 4.3 seconds, meaning optimization runs can take over 30 minutes to complete.
  • Symmetrical Context Contraction: Reduced the configured maximum sequence length limit (max_sequence_length) in config/settings.yaml and config/settings.dev.yaml to $32,768\text{ bp}$ ($2^{15}$ or $32\text{ kb}$).
  • Dynamic Config Binding: Refactored _adjust_locus_to_multiple in services/alphagenome_svc/app.py to dynamically read and clamp sequences against settings.limits.max_sequence_length instead of a hardcoded value. High-context regulatory areas are now cleanly centered and restricted to 32kb.
  • Massive Runtimes Speedup: By decreasing sequence lengths from 128kb to 32kb, the neural network's convolution steps execute 4x faster per pass. This shortens the entire interactive optimization and visualization wait time down to a fraction of its original duration (approximately 1 to 2 minutes on CPU).
  • Verification: Updated test_adjust_locus_to_multiple in tests/test_backend.py to expect the new $32,768\text{ bp}$ boundaries. Ran `pytest` to confirm that all test cases pass perfectly.

Standardized Log Propagation Hotfix for Background Services

May 24, 2026

Resolved the missing console/terminal logs issue by configuring centralized log level propagation on startup:

  • Root Cause Analysis: Discovered that python's root logger defaults to WARNING level when started from uvicorn without explicit configuration. This silently dropped all logger.info() calls in solver.py (including progress updates, percentages, and ETAs).
  • Early Logging Binding: Integrated explicit configuration loading in both services/alphagenome_svc/app.py and services/agent_backend/app.py by parsing and applying config/logging.yaml via logging.config.dictConfig at module import-time.
  • This ensures log levels and stream handlers are cleanly propagated to stdout/stderr inside the active terminals, making the real-time progress bar, percentage completions, and dynamic ETAs fully visible during long-running genomic edits optimization.
